## GB10 / sm_121 训练阻塞（rl-lab: /home/lab434/rl-lab，容器 slime_train）

**根因**：slime 镜像的 TE 2.10 + cuDNN 在 GB10（sm_121, Blackwell）上没有 flash-attention fused backward kernel。所有 megatron 训练 run 都死在 backward：`tex.fused_attn_bwd` → `cuDNN Error: No valid engine configs` → "Flash Attention with ragged offset can only be run with sm_90"（只支持 sm_90/sm_100，不含 sm_121）。前向/rollout 正常，reward 能算，一训练就崩。

**试过的方案及结论**：
- 直接设 `NVTE_FLASH_ATTN=0`/`NVTE_FUSED_ATTN=0` 环境变量 → Megatron `language_module.py` 硬断言拦截（提示必须用 `--attention-backend` 参数）。
- `--attention-backend unfused` → 配置确认生效（日志打印 `attention_backend: AttnBackend.unfused`），但 backward 仍走 cuDNN fused 路径，**没有真正绕开**。4B 和 0.5B 两次都死同一条错。
- slime `train.py` 只支持 `--train-backend megatron`（choices=["megatron"]），无 fsdp 等备选后端，绕不开 TE。
- 0.5B（`run_qwen25_05b_gb10_1gpu.sh`，用户 13:13 自跑，job `raysubmit_3EnSW2XA1zqNBU3b`）：rollout 质量明显更好（0% 截断 vs 4B 的 75%），但训练同样崩在 cuDNN backward。

**今天打过的补丁（容器内，重建镜像会丢）**：
- `/root/src/Megatron-LM/megatron/core/models/gpt/gpt_model.py`：`return self._postprocess(` 前加 `mtp_kwargs = (extra_block_kwargs or {}).get("mtp_kwargs") or {}`，修 `NameError: mtp_kwargs`（备份 `.bak_pre_mtp_fix`）。
- 显存调优：`--sglang-mem-fraction-static 0.25` + `MEM_FRACTION_STATIC=0.35`（0.45 会在 decode 阶段 OOM）。
- 4B-Thinking 在 512 max_response_len 下截断率 75%，回复太长；要出有效曲线需要更长上限或非 thinking 模型。
