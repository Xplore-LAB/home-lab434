## 3. 任务环境结构

- **数据格式**：Harbor 格式（parquet），每个任务包含：
  - `task.toml`：镜像摘要、一次性 setup、judge 设置、来源
  - `instruction.md`：agent 看到的 prompt
  - `environment/`：Dockerfile 和 setup/
  - `tests/`：grading 所需脚本
- **任务类型**：
  - `general_agent`：双容器（main + sidecar），agent 通过 MCP 工具调用业务系统
  - `terminal_bench`：单容器， baked into image
- **本地可用 runner**：`/home/lab434/rl-lab/mimo-docker/mimo_env_runner.py`（list|up|ports|verify|e2e|down）
- **Rollout 脚本**：`/home/lab434/rl-lab/mimo-docker/rollout2.py`

## 4. 关键设计（可用于研究）

### 4.1 双层评分机制
- **Rule-based**（VERIFY_DETERMINISTIC）：确定性检查，如 `source_data_present`
- **LLM Judge**（VERIFY_AGENT_JUDGE）：用 judge model（已验证 MiniMax-M3）评估答案质量
- 满分 1.0 需要所有 rubric items 全部通过

### 4.2 证据 grounding 要求
- **硬标准**：如果答案只基于 memo，即使写得很好也只能得 0.5/1.0
- agent 必须调用 MCP 工具从业务系统获取真实数据
- 验证案例：`s3k_0000_accounting_audit_tax_en_t1_rl_008`

### 4.3 训练创新
- **全异步架构**：Generation、Execution、Scoring、Training 四阶段并行
- **多任务混合训练**：Code、General Agent、Vision、Cybersecurity 混合在一个 RL run
- **Reward Hacking 防护**：Hack Agent 主动寻找答案泄漏，reward hacking 轨迹 < 2%
- **MoE Router 冻结**：RL 训练时冻结 router，防止 expert load collapse
- **Group Relative Scoring (GRS/GAR)**：多个 rollout 之间相对比较，不是简单的 pass/fail

## 5. 已知技术限制

- 官方镜像 `linux/amd64`，arm64 主机需要 QEMU 模拟（慢且不稳定）
- 双容器拓扑（main + sidecar）需要手动同步 workspace（关键步骤）
- MCP SDK 版本冲突：镜像内 mcp 2.2.0 与任务脚本的 v1 API 不兼容
- 完整 925 环境 sweep 需要 amd64 主机

## 6. 研究价值

| 研究方向 | 价值 |
|---|---|
| **Agent RL 训练** | 可直接用于复现小米的训练过程，研究 GRPO、mixed-task training |
| **Reward Hacking 防护** | 官方已实现并开源了 Hack Agent 机制，可作为 baseline |
| **MCP 工具使用** | 真实业务系统 grounding，不是 toy problem |
| **Multi-domain 迁移** | Code → General Agent → Vision → Cyber 的技能迁移 |
| **蒸馏研究** | 官方已蒸馏出 9B 模型，社区可继续蒸馏更小模型 |

## 7. 下一步实验计划

1. **环境就绪检查**
   - 确认 Docker 可用
   - 确认数据集已下载
   - 确认 runner 脚本可用

2. **单任务 Smoke Test**
   - 启动 `s3k_0000_accounting_audit_tax_en_t1_rl_008`
   - 验证 MCP 工具可调用
   - 验证 sidecar workspace 同步机制
   - 目标：reward = 1.0

3. **批量实验**
   - 选择 5-10 个不同类型的任务
   - 用 rollout2.py 跑 baseline
   - 记录通过率、token 消耗、运行时间

4. **研究问题**
   - Q1：不同任务类型之间的 RL 迁移效果如何？
   - Q2：Reward hacking 防护在不同 domain 的有效性？
   - Q3：蒸馏模型（9B）在真实业务任务上的表现？
